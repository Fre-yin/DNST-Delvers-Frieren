# Contributing / Mitwirken

## Deutsch

Fehlermeldungen, Vorschläge, Dokumentation, Übersetzungen und gezielte Codeänderungen für Dungeon Settlers Delvers: Frieren sind willkommen. Beiträge und Rückfragen sind auf Deutsch oder Englisch möglich. Bitte beachte den [Verhaltenskodex](CODE_OF_CONDUCT.md).

### Fehler melden

Prüfe zuerst die README, die Hinweise zur aktuellen Veröffentlichung und bestehende Issues. Nutze für neue Fehler die Vorlage. Gib an, welche Versionen von Frieren, Core, dem Spiel, dem Loader und Windows du nutzt. Nenne auch andere relevante Mods, Schritte zum Nachstellen sowie das erwartete und tatsächlich beobachtete Verhalten. Bereinigte Protokolle oder Screenshots können helfen.

Veröffentliche keine Zugangsdaten, privaten Schlüssel oder persönlichen Spielstände. Entferne persönliche Informationen aus Anhängen. Sichere deine Spielstände, bevor du Änderungen im Spiel ausprobierst.

### Sicherheitslücken

Melde vermutete Sicherheitslücken vertraulich über den Weg in der [Sicherheitsrichtlinie](SECURITY.md). Erstelle dafür kein öffentliches Issue.

### Vorschläge und Übersetzungen

Beschreibe bei Funktionswünschen das Problem, den gewünschten Ablauf und den Nutzen. Besprich größere Änderungen zuerst in einem Issue. Bei Übersetzungen nenne Sprache, betroffenen Text und deinen Vorschlag.

### Code und Pull Requests

- Halte Änderungen klein und auf ein Thema begrenzt.
- Nutze einen eigenen Branch und öffne einen Pull Request gegen `main`.
- Beachte die [Bauanleitung](BUILDING.md) und die Kompatibilität mit der angegebenen Version von Core. Prüfe MelonLoader und BepInEx getrennt, wenn beide betroffen sind.
- Erkläre im Pull Request, was sich ändert und warum. Verlinke ein zugehöriges Issue, falls vorhanden.
- Nenne durchgeführte Prüfungen, Ergebnisse und nicht geprüfte Fälle. Aktualisiere betroffene Dokumentation.
- Füge keine Spieldateien, persönlichen Spielstände, Zugangsdaten, privaten Schlüssel oder Grafiken ohne geklärte Rechte hinzu. Erzeugte Builds und Archive für Veröffentlichungen gehören nicht in Pull Requests für den Quellcode.

Versionsänderungen und Veröffentlichungen werden mit dem Maintainer abgestimmt. Bestehende Tags und Dateien bereits veröffentlichter Versionen dürfen nicht still ersetzt werden. Das Projekt wird in der Freizeit betreut; eine feste Bearbeitungsfrist oder Übernahme jedes Vorschlags kann nicht zugesichert werden.

## English

Bug reports, suggestions, documentation, translations, and focused code changes for Dungeon Settlers Delvers: Frieren are welcome. Contributions and questions may be written in German or English. Please follow the [Code of Conduct](CODE_OF_CONDUCT.md).

### Reporting bugs

Check the README, current release notes, and existing issues first. Use the bug template for a new report and include Frieren and Core versions, game version, loader and its version, Windows version, other relevant mods, steps to reproduce, and expected and actual behavior. Sanitized logs or screenshots may help.

Do not publish credentials, private keys, or personal game saves. Remove personal information from attachments. Back up your saves before trying changes in the game.

### Security vulnerabilities

Report suspected vulnerabilities privately using the channel in the [Security Policy](SECURITY.md). Do not open a public issue.

### Suggestions and translations

For feature requests, describe the problem, the desired behavior, and the benefit. Discuss substantial changes in an issue first. For translations, include the language, affected text, and your proposed wording.

### Code and pull requests

- Keep changes small and focused on one topic.
- Use a separate branch and open a pull request against `main`.
- Follow the [build instructions](BUILDING.md) and the stated Core compatibility. Check MelonLoader and BepInEx separately when both are affected.
- Explain what changes and why. Link a related issue, if any.
- State which checks you performed, their results, and any cases you did not check. Update affected documentation.
- Do not include game files, personal saves, credentials, private keys, or artwork without clear rights. Keep generated builds and release archives out of source-code pull requests.

Coordinate version changes and releases with the maintainer. Existing tags and release assets must not be silently replaced. This project is maintained in spare time; review times and acceptance of proposals are not guaranteed.
